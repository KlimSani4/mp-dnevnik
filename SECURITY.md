# Безопасность

## Как сообщить об уязвимости

Не создавайте публичный issue. Используйте [приватный отчёт](../../security/advisories/new) (Security → Report a vulnerability) и опишите:

- что уязвимо и где;
- шаги воспроизведения;
- возможные последствия.

Мы ответим в течение 7 дней.

## Поддерживаемые версии

Исправления выпускаются только для последней версии из ветки `main`.

## Результаты аудита

Отчёт о внутреннем ИБ-аудите (#98): [docs/security-audit.md](docs/security-audit.md). Последний аудит: 26.10.2026, ориентир OWASP ASVS уровень 1.

Что проверяется автоматически в CI: `bandit`, `pip-audit`, `pnpm audit --prod`, регрессионные тесты доступа в `backend/tests/test_security/`. Зависимости обновляет Dependabot.

## Правила для разработчиков

- Каждый маршрут, который отдаёт или меняет данные группы, проверяет членство и роль пользователя в этой группе; доступ по `id` без проверки владельца недопустим.
- Маршруты `/api/v1/internal/*` предназначены только для бота и требуют заголовок `X-Internal-Secret`; снаружи они закрыты в nginx.
- Пользовательский текст в сообщениях бота экранируется через `html.escape`.
- Ссылки, введённые пользователем, принимаются только со схемой `http` или `https`.
- Секреты хранятся только в переменных окружения и Kubernetes Secrets; в репозиторий попадают только `.env.example` с примерными значениями.
- В production задаётся `APP_ENV=production`; при `development` включается вход без Telegram.
- Новая находка уровня «средне» и выше: отдельный issue с меткой `security` и запись в `docs/security-audit.md`.
