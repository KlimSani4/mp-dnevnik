# Как вносить изменения

## Задачи

- Любая работа начинается с issue. Шаблоны: баг, фича.
- Issue берут на себя через Assignees и ведут на доске GitHub Projects.
- Крупная задача разбивается на issues по 1–3 дня работы.

## Ветки

| Ветка | Назначение |
|---|---|
| `main` | Стабильная версия, то, что задеплоено. Прямые пуши запрещены |
| `feat/<issue>-<кратко>` | Новая функциональность, напр. `feat/42-ics-export` |
| `fix/<issue>-<кратко>` | Исправление бага |
| `docs/<кратко>` | Документация |
| `chore/<кратко>` | Инфраструктура, зависимости, CI |

## Коммиты

Формат [Conventional Commits](https://www.conventionalcommits.org/ru/):

```
<тип>(<область>): <что сделано>
```

| Тип | Когда |
|---|---|
| `feat` | Новая функциональность |
| `fix` | Исправление бага |
| `docs` | Документация |
| `refactor` | Рефакторинг без изменения поведения |
| `perf` | Производительность |
| `chore` | Сборка, зависимости, CI |

Примеры: `feat(schedule): экспорт в ICS`, `fix(tasks): перемещение виджетов на мобильных`.

## Pull request

1. Ветка от актуального `main`.
2. PR ссылается на issue: `Closes #42`.
3. Заполнен шаблон PR, приложены скриншоты для изменений UI.
4. Минимум один approve от другого участника команды.
5. Слияние через Squash and merge.

## Код

- Кодировка UTF-8, отступы и переводы строк — по `.editorconfig`.
- Секреты (токены бота, ключи, пароли БД) не коммитятся никогда. Только через переменные окружения; образец переменных — `.env.example` в папке компонента.
- Пользовательские тексты интерфейса — на русском.
